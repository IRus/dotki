# Dotki

Две игры на клетчатой бумаге: **Точки** на A5 и **крестики-нолики до пяти** на бесконечном поле. Можно играть с другом по сети или против ИИ.

UI — Kotlin/JS + **закреплённая сборка Kinetica**. Сервер — настоящий **Kotlin/Native** executable с Ktor/CIO, без JVM во время работы. Gradle и компилятор требуют JDK. Общие правила и протокол находятся в `shared`; JVM используется только для быстрых тестов.

## Запуск

Нужны JDK 21+ (проверено на 25), Python 3.12+, Git и Xcode Command Line Tools на macOS. Kinetica загружается автоматически: commit и SHA-256 архива закреплены в `dependencies/kinetica.lock.json`.

```sh
# Скачать проверенный snapshot Kinetica и собрать его в mavenLocal.
./scripts/build-kinetica.sh

# Собрать UI и нативный сервер, затем запустить сервер.
./scripts/dev.sh
```

Открыть **http://localhost:8080**, создать игру и передать ссылку второму игроку. В одном браузере для второго игрока нужна отдельная вкладка, открытая независимо, или другое окно/профиль. Ключ игрока хранится в `sessionStorage` и переживает перезагрузку страницы; копирование вкладки браузером может скопировать и этот ключ. Для двух устройств в локальной сети использовать адрес компьютера, например `http://192.168.1.10:8080`.

Соседний checkout Kinetica не нужен. `scripts/build-kinetica.sh` скачивает исходники в игнорируемый `.local/kinetica/`, проверяет SHA-256 и применяет закреплённый patch с Canvas/AppKit API, которые пока не вошли в upstream. Артефакты получают отдельную версию `0.4.0-dotki.1`, поэтому обычная локальная Kinetica 0.4.0 не перезаписывается. Разрешение Kinetica идёт **только из mavenLocal**. Подробности и порядок обновления — [dependencies/README.md](dependencies/README.md).

Настройки сервера:

```sh
HOST=0.0.0.0 PORT=8080 \
WEB_ROOT=web/build/dist/js/productionExecutable \
server/build/bin/native/debugExecutable/server.kexe
```

На Apple Silicon собирается `macosArm64`, на Linux — `linuxX64` или `linuxArm64` по архитектуре хоста. Имя Gradle target одинаковое: `native`. Linux-конфигурация предусмотрена, но локально проверена macOS ARM64.

Для оптимизированного бинарника: `./gradlew :server:linkReleaseExecutableNative`. Для публикации в интернете нужен reverse proxy с HTTPS и поддержкой WebSocket; фронтенд и `/ws` должны быть на одном origin, proxy должен сохранять заголовок `Host`.

## Как играть

На каждой карточке `Начать ↗` создаёт комнату для игры с другом, а `Против ИИ` сразу запускает одиночную партию. Человек играет красными / крестиками и ходит первым. Бот занимает синее место; другой человек не может его занять. После завершения `Сыграть ещё раз ↗` сразу начинает новую партию, без ожидания второго игрока.

ИИ работает на сервере без нейросети, внешних API и ключей. На обеих карточках доступны уровни **Medium** и **Hard**. По умолчанию выбран Medium. Сложность сохраняется при переподключении и реванше.

- **Medium** — исходные алгоритмы. В пяти в ряд ищет немедленную победу, блокирует победный ход соперника и оценивает открытые и разорванные линии. В «Точках» рассматривает до 96 перспективных свободных пересечений, проверяет захват и защиту через правила игры, избегает чужих домиков. После паса человека также пасует, если в рассмотренных ходах нет немедленного захвата. Исходный алгоритм точек сохранён в `DotsMedium.kt` без изменения его оценок и порядка выбора.
- **Hard** — ограниченный negamax/minimax с альфа-бета-отсечением и постепенным увеличением глубины. «Точки»: до 3 полуходов, оценка счёта, связности и опасности окружения; рассмотрение захватов и блокирующих ходов при упорядочивании. Пять в ряд: основная глубина до 4 полуходов; вынужденные защиты продлеваются ещё до 4 полуходов за горизонтом, чтобы не пропускать неизбежные угрозы. На первом уровне остаются 12 лучших ходов, на последующих — до 6–8. Поиск ограничен примерно 3 секундами и 15000 проверок для точек / 300000 для пяти в ряд. Если глубокий проход не завершён, используется последний полностью завершённый. Это не полный перебор и не гарантия оптимальной игры.

Для точек Hard использует быстрый симулятор на массивах, проверяемый дифференциальными тестами против `Rules`. Захваты окончательно применяются обычным серверным `Rules`, независимо от уровня. В тактических тестах Hard защищает две точки вместо захвата одной с последующей потерей двух и не принимает проигрыш пасом. Более сильная тактика пока не означает доказанный перевес на большой выборке партий.

Поиск выполняется вне блокировки комнат. Отключение человека отменяет поиск; переподключение возобновляет ход ИИ. Результат старого поиска не может попасть в новую партию после сдачи или реванша.

**Отмена хода:** после постановки знака/точки или паса на 5 секунд появляется кнопка с обратным отсчётом. Отмена доступна только последнему ходившему игроку, пока соперник не ответил. Сервер проверяет срок по монотонным часам; на отметке 5000 мс окно закрывается. При отмене восстанавливаются поле, захваты, счёт, очередь и результат партии; версия состояния увеличивается, поэтому старые команды нельзя повторить. Незавершённый поиск ИИ отменяется. После ответа ИИ отменить свой предыдущий ход уже нельзя. Сдача не отменяется.

**Точки**

- Лист A5 — 148 × 210 мм. Помещается 29 × 42 полных клетки по 5 мм: игровая сетка 145 × 210 мм, **30 × 43 пересечения**. Физический размер на экране зависит от масштаба и устройства.
- Красные ходят первыми. Точки ставятся на свободные пересечения по очереди.
- Соседние свои точки по стороне или диагонали замыкают контур. Край бумаги сам по себе не служит стеной.
- Контур с чужими точками захватывает их и внутреннюю область. Одно очко за каждую захваченную чужую точку; внутри захваченной области новые ходы запрещены.
- Захваченные точки не образуют стены. Более крупное окружение может освободить свои точки и изменить счёт.
- Пустой контур — «домик»: остаётся доступным, но вошедшая чужая точка захватывается. Если входящий ход сам захватывает соперника, собственный захват имеет приоритет.
- Два паса подряд или отсутствие доступных пересечений завершают партию; побеждает больший счёт. Равный счёт — ничья.

**Пять в ряд**

- Крестики начинают. Пять **или больше** подряд по горизонтали, вертикали или диагонали — победа. Запретов рэндзю нет.
- Крестики и нолики ставятся **в центрах клеток**; клик в любом месте клетки выбирает её. В «Точках» используются пересечения сетки.
- Поле хранится как разреженный набор ходов, без заданной ширины или высоты. Техническое представление координат — знаковый 32-битный `Int`; арифметика проверки победы не переполняется на его границах.
- Перетаскивание двигает поле; колесо, щипок и кнопки `−`/`+` меняют масштаб. `⌖` возвращает к последнему ходу.
- С клавиатуры: Tab на поле, стрелки выбирают точку, Enter/пробел делает ход; Home возвращает к последнему ходу.

Обе игры поддерживают сдачу и реванш по согласию обоих игроков. При потере соединения партия приостанавливается, место сохраняется, клиент переподключается автоматически.

## Состояние и протокол

`/ws` — WebSocket с JSON-сообщениями из `shared/Protocol.kt`. Первое сообщение — `create` или `join`; сервер отвечает `welcome` с личным ключом и затем рассылает `state`. Ключ не попадает в общую ссылку или состояние соперника. Ходы содержат ожидаемую `revision`; проверки очереди, координат, занятости, завершения и версии выполняются атомарно на сервере. Повторный ход со старой версией не применяется. Реванш сохраняет монотонную версию.

Активные комнаты хранятся **в памяти одного процесса**: после перезапуска продолжить прежнюю партию пока нельзя. При этом все новые сессии и их история записываются в **SQLite** и сохраняются после перезапуска. Полностью отключённые комнаты удаляются из памяти через 6 часов, архив остаётся; лимит активных комнат — 512. Аккаунтов и подбора случайного соперника пока нет. Новое соединение с тем же личным ключом заменяет старое.

## Проверка

```sh
./gradlew :shared:jvmTest :server:jvmTest :shared:nativeTest :server:nativeTest
./gradlew :web:jsBrowserDistribution :server:linkDebugExecutableNative
npm ci
npx playwright install chromium
npm test

# Воспроизводимые парные партии medium vs hard со сменой цветов.
# Незавершённые за 120 ходов партии помечаются unfinished, а не победой/ничьей.
./gradlew :server:compareBots
```

Тесты правил проверяют захваты, домики, перезахват, край листа, пас, все направления победы, разрывы линий и переполнение координат. Тесты комнат проверяют конкурирующие ходы, личные ключи, переподключение, отключение, реванш и срок хранения. Тесты ИИ проверяют победные ходы, блокировку угроз, захват, защиту, домики, отмену поиска и защиту от устаревших результатов. Браузерные тесты запускают нативный сервер, играют двумя независимыми сессиями и против ИИ, проверяют центры клеток и управление полем.

Сравнение 26.10.2026 на JVM при прежнем лимите поиска 1,2 секунды: на двух фиксированных началах со сменой цветов Hard в пяти в ряд выиграл 3 партии из 4; четвёртая не завершилась за 120 ходов. В точках все 4 партии остались незавершёнными (счёт 1:1 или 0:0). Выборка маленькая и не доказывает общий процент побед; результаты поиска могут различаться на другой машине из-за временного лимита.


## Docker и опубликованный экземпляр

Публичный адрес: https://dotki.heapyhop.com. Клиент — Kotlin/JS + закреплённая сборка Kinetica; сервер — Kotlin/Native + Ktor CIO, без JVM.

```sh
# На машине с опубликованной в mavenLocal Kinetica:
./scripts/package-linux.sh linuxArm64
# На Linux ARM64 с Docker, после переноса build/docker-context-linuxArm64:
docker build --build-arg DOTKI_VERSION=20261026-sqlite-edge-v1 -t dotki:20261026-sqlite-edge-arm64 build/docker-context-linuxArm64
# Проверка уже запущенного экземпляра без локального сервера:
DOTKI_BASE_URL=https://your-dotki.example npx playwright test
```

GitHub Actions собирает и проверяет Linux ARM64 образ `ghcr.io/irus/dotki`.
Для каждого прошедшего проверку commit публикуются теги `sha-<полный SHA>` и `main`.
В конфигурации развёртывания закрепляйте digest `@sha256:…` из успешной сборки.
Перед публикацией CI проверяет JVM/native-тесты, HTTP, статические файлы и
сохранность SQLite после перезапуска контейнера на отдельном временном томе.

Для развёртывания используйте reverse proxy с HTTPS и поддержкой WebSocket.
Healthcheck — `/health`; данные SQLite нужно хранить в постоянном томе `/data`.
Контейнер работает под UID/GID 65532. Перезапуск сбрасывает активные комнаты,
но сохраняет архив сессий. Инфраструктурная конфигурация хранится отдельно.

## Архив сессий SQLite

Нативный сервер всегда открывает SQLite через SQLiter 1.4.0. Локально файл — `.local/dotki.sqlite`; `DOTKI_DB_PATH` задаёт другой путь. В Docker это `/data/dotki.sqlite`, постоянный именованный том `dotki-data` (не удалять при обновлениях). WAL и `synchronous=FULL`; каждое событие и последнее состояние сессии коммитятся одной транзакцией **до** подтверждения клиенту. При отказе записи сервис перестаёт принимать игры, а `/health` возвращает 503. Режима молчаливой работы без архива нет.

Сессия — комната с уникальным UUID, включая её реванши. Таблица `sessions` хранит код комнаты, игру, режим, сложность ИИ, версию сборки, время создания/обновления и последнее состояние. `events` хранит упорядоченный по `id` журнал: создание, вход/переподключение/отключение, ходы, пасы, отмены, сдачи, реванши и истечение срока активной комнаты. JSON содержит состояние до игрового действия и полный снимок комнаты после него, координаты и игрока. Для ИИ сохраняются выбранный ход, длительность самого поиска без паузы 350 мс, отменённые и отброшенные результаты. Время событий — Unix milliseconds UTC; длительность поиска — монотонные часы.

Имена игроков сохраняются, личные ключи комнаты и IP-адреса — нет. Архив не публикуется через HTTP; доступ — через SSH/SQLite. Автоматического удаления архивных сессий нет. При запуске старые незакрытые сессии помечаются `server_restart`; это архив для анализа, а не восстановление сетевой игры. Партии до включения архива восстановить нельзя.

```sh
# Список сессий контейнера, без личных ключей (их в БД нет).
docker exec dotki sqlite3 -readonly -header -column /data/dotki.sqlite \
  'SELECT id, room_code, kind, mode, bot_level, app_version, last_revision, closed_reason FROM sessions ORDER BY started_at DESC LIMIT 20;'
# Проверка целостности:
docker exec dotki sqlite3 -readonly /data/dotki.sqlite 'PRAGMA integrity_check;'
# Согласованная резервная копия живой WAL-базы; не копировать только основной .sqlite-файл:
docker exec dotki sqlite3 /data/dotki.sqlite ".backup '/data/dotki-backup.sqlite'"
docker cp dotki:/data/dotki-backup.sqlite ./dotki-backup.sqlite
# События конкретной сессии:
sqlite3 -readonly dotki-backup.sqlite "SELECT payload_json FROM events WHERE session_id='UUID' ORDER BY id;"
```

Для кросс-сборки `package-linux.sh` автоматически получает библиотеку SQLite ARM64/x64 из официального Debian bookworm, проверяет SHA-256 пакета и использует её только при линковке. В контейнере библиотека устанавливается через APT. На Linux при ручной сборке Gradle нужен `libsqlite3-dev` либо параметр `-PsqliteLibraryDir=...`.

**Исправление Hard у края:** оценка больше не считает угрозой окружение точек, которые соединены с внешним краем непрерывной цепью своего цвета по сторонам. Диагональная связь или разрыв цепи такой защиты не дают. Ходы на крайней линии остаются доступны для настоящих захватов внутри листа. Medium и правила игры не менялись.


## Приложение macOS

Нативный клиент Kotlin/Native + Kinetica подключается к `https://dotki.heapyhop.com`. Поддерживает обе игры, Medium/Hard, комнаты с браузерными и десктопными игроками, отмену хода, сдачу, пас и реванш. ИИ и архив SQLite остаются на сервере. При временной потере сети клиент переподключается; ключ комнаты хранится в памяти до закрытия приложения.

Требования этой сборки: Apple Silicon, macOS 14+. JVM, браузер и WebView не нужны. Исходники `desktop/src` используют только Kinetica и переносимые Kotlin/Ktor API. Окно, меню, буфер обмена и рисование реализованы внутри закреплённой Kinetica; её macOS backend использует AppKit.

```sh
# Загрузка и сборка закреплённой Kinetica, включая Canvas и desktop API:
./scripts/build-kinetica.sh
# Release .app и ZIP с локальной ad-hoc подписью:
./scripts/package-macos.sh release
open build/macos/release/Dotki.app
# Проверки геометрии и сетевые интеграционные тесты:
./gradlew --no-daemon :desktop:jvmTest :desktop:nativeTest
```

Результаты: `build/macos/release/Dotki.app` и `build/macos/release/Dotki-macos-arm64.zip`. Это локальная сборка без Developer ID и нотарификации Apple. Скрипт не отправляет артефакты в registry или GitHub.

`nativeTest` подключается к публичному серверу и создаёт тестовые сессии, которые попадают в общий архив. Проверяет партии против Hard, мультиплеер и отмену хода, а также сохраняет изображения собственных Kinetica views в `/tmp/dotki-desktop-qa`. Для отдельного сервера исполняемый файл принимает `--server=https://example.com` (для локальной разработки допускается `http://127.0.0.1:PORT`).

Поле можно перемещать перетаскиванием, масштабировать колесом/щипком или кнопками. Стрелки выбирают клетку/точку, Enter делает ход, Home переводит к последнему ходу. В пяти в ряд знаки находятся в центрах клеток.
